# 场段图编辑器 GitHub 产品说明与发布设计

## 1. 目标

将现有“线路/场段详图编辑器”拆分为独立的“场段图编辑器”静态工具，发布到 GitHub。工具面向场段图配置人员和场段业务使用者，可在浏览器内绘制与维护场段股道图、导入 PDF 作为底图、配置区域/供电/信号/道岔等对象，并在运行发布页标记股道状态、停放车辆和安全设备。

本仓库不包含正线详图绘制、站点字典、正线运行发布页或任何真实基地图纸、业主资料、账号口令与现场运行数据。

当前公开版本为 `v1.0.0`。它以已验证的场段编辑器为基础，在页面最终入口处统一限定为“场段模式”：公开使用者默认进入空白通用工程，导入和导出都以场段 JSON 为边界，界面不提供正线或登录入口。这样保留成熟的场段绘制和运行标记能力，同时避免公开工程混入内部业务内容。

## 2. 发布范围

### 保留能力

- 场段编辑页：PDF 底图、画布平移缩放、股道/区域/线段/文本/道岔/信号机绘制、对象属性、图层、数据字典、对齐参考、JSON 工程导入导出。
- 场段运行发布页：股道状态、供电状态、车辆停放、拆分编组、安全设备、图例、对象详情、全屏大屏页与运行状态同步。
- 本地数据：浏览器本地草稿与运行状态；JSON 文件用于工程交接、备份及导入。
- 示例：脱敏的示例工程，仅演示对象类型、状态和操作流程。

### 明确剔除能力

- 正线编辑、车站字典、站点缩略图、正线图层、正线发布页、正线打印折行及相关缓存键。
- 登录界面及前端账号校验。静态网页不能提供真实权限控制。
- 小行基地、南京地铁或其他运营单位的真实图纸、车辆编号、人员数据、运作规则和 PDF 文件。

## 3. 架构与数据边界

发布版保持纯静态 HTML、CSS 和 JavaScript，不依赖后端服务。页面在浏览器内完成绘图和运行状态处理；工程配置与运行状态分别写入浏览器本地存储，用户可导出 JSON 做备份或交换。

工程 JSON 不包含底图原文件本体。PDF 底图仅在当前浏览器会话中导入和显示；导出工程后，使用者需要在新环境重新导入底图。这样既避免大文件进入 GitHub，也避免图纸被工程文件意外带出。

公开仓库只提供脱敏示例。真实项目应使用内部部署版或私有仓库，并按运营单位信息安全制度管理。

## 5. GitHub 页面与版本发布

仓库首页通过 GitHub Pages 发布，页面入口为根目录的 `index.html`。在线版仅用于演示与脱敏配置；浏览器本地数据不自动上传 GitHub。

首个 Release 使用标签 `v1.0.0`，提供：在线访问地址、变更说明、离线 ZIP 包以及示例工程说明。后续新增功能按 `v1.1.0`、`v1.2.0` 递增；修复问题按 `v1.0.1` 递增。GitHub Actions 工作流已配置为：`main` 分支更新后发布 GitHub Pages。

## 6. README 图文结构

README 使用中文，包含：产品定位、核心能力、适用对象、运行方式、编辑流程、运行发布流程、JSON 工程说明、截图展示区、数据安全边界、版本与贡献说明。

README 已包含四张成果截图，分别为：

1. 场段编辑页全景。
2. 选中股道后的属性与对象配置。
3. 运行发布页的车辆、安全设备及供电图例。
4. 全屏大屏页。

截图均放在 `docs/images/` 并由 README 直接引用。截图使用导入工程的图形配置展示编辑能力；车辆、安全设备和运行状态为展示性补充数据，不表示现场实时运行状态。后续替换截图时，应继续避免出现账号口令、浏览器个人信息及未获授权的资料。

## 7. 验收标准

- 仓库打开后可从 README 清楚理解用途和操作方法。
- `index.html` 在 Chrome、Firefox、Edge 中可直接打开；GitHub Pages 可在线打开。
- 正线功能、真实图纸和真实运行数据均不在公开发布包内。
- 示例工程可导入、编辑、发布、打开运行页和全屏页。
- 编辑页、运行页和全屏页的运行状态同步不互相覆盖。
- README、示例工程与实际界面功能一致。

## 8. 后续边界

本次发布目标是可离线使用、可在线展示、可继续开发的工具版本，不是正式生产部署。账号权限、多人协作、服务端保存、审计日志、第三方系统实时数据接入和正式接口鉴权需要在后续服务端版本单独建设。
